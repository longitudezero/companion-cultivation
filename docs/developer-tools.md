# Player controls and developer tools — Prototype 16

This page describes **the current interface**, not a new or finalized gameplay design. The separation is an interface safeguard against accidental sandbox editing. It does not disable capabilities in the deterministic core API or provide an anti-cheat security boundary.

## Toggle and default view

The top bar, next to the Companion Cultivation logo, offers **Display developer tools**. It is **off by default on page load**. Click it to show a separate **Developer tools · test only** section and other test-only controls throughout the interface. Click **Hide developer tools** to return to the player-facing view.

If a debug placement tool is active when the developer tools are hidden, the selection automatically returns to ordinary inspection. Existing garden objects, environmental state, and inventories are **not** altered. Browser-local garden saving is unchanged. The visibility preference is intentionally not stored with the garden.

### Always visible (provisional player-facing interface)

- **Inspection:** Select a hex directly; its portrait/name, resolved Conditions, lifecycle and current harvest amounts appear in the bottom inspector. Its fixed order is portrait, Environment, Growth & Harvest, Influence cards, then an active Transformation segment. The ordinary mode toolbar has been removed. Exact undiscovered Transformation recipes, hidden Fungus effects and hazard thresholds no longer appear in the ordinary inspector.
- **Taskboard:** The noticeboard icon beside the Grimoire opens Main/Side/Completed sections with the first two tutorial tasks and one basic Carrot Leaf delivery. Fulfilled goals mark a task ready; Complete task awards its whole reward once and shows a receipt. The first claim supplies Dewmender and opens A Thirsty Carrot. Pin/unpin tasks and collapse the upper-right garden tracker by clicking Objectives. Speed/zoom controls sit at upper left. The side task requires 5 currently held Carrot Leaves and explicitly consumes them for a provisional 10 Gold. Use New tutorial garden for a confirmation-gated fresh 4 × 4 starter; existing sandboxes are retained until explicitly replaced. The board shares Pause/0.5×/1×/2× and never changes speed on opening.
- **Cultivation Grimoire:** The top-bar **❦ Cultivation Grimoire** opens the approved bound-book UI with all Fungi and six starting Plants identified, and progressively reveals environmental observations, fungal interactions and successful Transformation witnesses. Its eight fixed-height colored bookmarks change sides with the hinged page turn. Knowledge is per garden and included in browser autosaves and `.ccsave` backups; all 60 Plants and 13 Fungi use the supplied illustrations once identified. See [Grimoire design](design/systems/cultivation-grimoire.md).
- **Spatial inventory:** Four collapsible pages of 50 squares each (200 total); Seeds, Spores, Leaves and trophies retain their existing unlimited stacks. Each temporary Source item is an individual, non-stacking inventory tile with its own paused remaining lifetime. Drag tiles to reposition or swap them; positions persist. Type filters show the same saved stacks, with species names/illustrations, type-colored accents and upper-right quantities (Seeds yellow, Spores purple, Leaves green, Items sky blue). Squares stay 80 × 80 px; drag the left boundary to reveal more columns. Fast non-interactive hover cards show useful known information. The inventory becomes a drawer on narrow screens.
- **Temporary Source items:** Drag a stored item onto an empty hex to start its countdown, directly to another empty hex to move it, or back to inventory to pause it. Deployed items free their inventory squares. If the inventory is full, pickup is refused without losing the item; its timer continues while placed. Select a Budget item to show the floating six-way rotation handle, or use the inspector direction buttons. At zero remaining time the item disappears permanently. The store and unlock triggers are not yet implemented; item acquisition is developer-only for now.
- **Planting from inventory:** Drag an owned Seed/Spore stack onto a hex, or select the stack and click the target hex. Choose an amount with the editable quantity box, ± buttons or example presets. This stages a **reservation**, not a charge. Existing germination and habitat rules still apply at Apply.
- **Staging, Apply, Undo and Cancel:** Reposition or edit uncommitted proposals. The lower-left **Undo** reverses the last staging action; **Cancel** clears the entire current phase and releases reservations. Neither changes live growth or previous committed attempts. Select a staged Fungus with Budget propagation to rotate its heading using the floating six-way handle; its heading freezes after Apply. **Apply** validates every site and commits them together, spending Seeds/Spores exactly once. Committed `?` markers conceal either a successful or failed roll until the delay expires. Another plan can begin immediately, even while earlier plots are pending. Select a pending hex to see Germinating… centered in its public progress bar. Action results and errors appear briefly inside the garden above Apply.
- **Harvest:** Drag a living Plant/Fungus from its hex into the inventory. Clicking the bottom portrait opens its exact Grimoire page. Keyboard pickup controls are deferred to a later design pass. There is no permanent Harvest button in ordinary play. An itemized harvest receipt appears at the garden’s lower-right edge beside inventory for four seconds. Its existing one-time yield and restrictions remain in effect; outputs merge into species-specific stacks.
- **Garden camera:** Wheel/pinch or ± zoom around the current view; Fit frames the whole plot. Drag empty ground to pan, or use the middle mouse button anywhere, including occupied hexes. Resizing the window or inventory reveals more/less garden without changing hex size.
- **Environment, plot contents and clock:** Inspection remains available. Pause/0.5×/1×/2× control the whole simulation. When running, the clock **advances automatically even while staging**, so existing Growth, Transformations, hazards and Mycelial activity update live. Existing Sources/Blockers keep affecting the simulation even when editing them is hidden.
- **Autosave, Save Game and Load Game:** The header reports whether writing to browser-local storage succeeded. Save Game downloads a complete portable `.ccsave` snapshot; Load Game validates a `.ccsave` or older `.json` garden, then asks for confirmation before replacing the active garden and browser autosave. Both work during staging or pending germination and do not spend items or advance time. See [saving and backups](design/systems/saving-and-backups.md).

## Still awaiting design

**Player-placeable Blockers** remain undecided. Hex and Edge Blocker placement are *both developer-only* for now; later designs may expose specific approved blocker items through different player actions. No new blocker costs, restrictions or mechanics were invented in this pass.

At **1× the game advances one simulated garden hour every five real seconds**, independently of staging. The garden HUD beside zoom/Fit provides Pause, 0.5×, 1× and 2×. Pausing retains partial elapsed time and allows planning; every elapsed-time system uses the same multiplier. Grimoire durations use the 1× baseline: e.g. a 16-hour recipe is **1m 20s**. The selected Source item timer accounts for current speed. Developer `+5s` / `+2m` buttons still skip one game hour / one game day instantly, even while paused. A committed germination stays concealed for six simulated hours (**30 real seconds at 1×**); that reveal duration remains provisional. Speed and inventory width are browser preferences, separate from garden backups. No closed-page catch-up is implemented.

The [approved spatial-inventory and repeatable staging specification](design/systems/spatial-inventory-and-staging.md) remains authoritative for the interaction and safety rules; this guide describes its **first working implementation**. The initial six Seed stacks are prototype stock; player acquisition of starter Spores and relocation of living organisms with a future item have not been designed. Debug-only JSON export exposes full technical state, including concealed germination outcomes, and therefore should remain behind the developer toggle.

Portable `.ccsave` backups are likewise readable JSON containing the entire state; the player-facing UI keeps concealed results hidden, but files are not encrypted. There is no account-based sync or automatic game-time catch-up while the browser is closed. File downloads use the browser's normal downloads folder or browser-configured destination.
